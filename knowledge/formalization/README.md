# 数学知识 × 逻辑推理

数学知识回答“可以使用什么”，逻辑推理回答“为什么能从当前事实推出下一事实”。MathAI 将二者统一为可检查的六元组：

```text
概念定义 + 定理陈述 + 适用前提 + 推理规则 + 新结论 + 验证证据
```

## 推理分层

| 层 | 内容 | 仓库载体 |
|---|---|---|
| 语义层 | 自然语言题意、概念内涵与外延 | `knowledge/` |
| 知识层 | 定义、定理、公式、反例 | `knowledge/` |
| 规划层 | 选择定理并排列子目标 | `skills/` |
| 推理层 | `前提 ⊢ 结论` 的原子步骤 | 解答记录 |
| 计算层 | 代数、数值、符号运算 | `tools/` |
| 形式化层 | 类型正确的证明项 | `formal/lean/` |

## 原子推理记录

每一步不得只有公式变形，必须记录：

```yaml
goal: 要证明的新结论
facts: [当前可用事实]
theorem: 使用的定理或定义
assumptions:
  required: [定理要求的前提]
  discharged: [前提如何得到证明]
inference: 代入、重写或推导过程
result: 得到的结论
evidence:
  kind: lean | sympy | numeric | manual
  status: pass | fail
  reference: 证明文件、命令或说明
```

这种结构能阻止三类常见错误：

1. **公式对但条件不满足**：例如对不可导函数误用链式法则。
2. **局部等价被当成全局等价**：例如约去可能为零的因子。
3. **结果碰巧正确但过程错误**：最终答案不能覆盖中间的 `FAIL`。

## 从知识到证明

```text
自然语言问题
  → 明确变量类型和量词
  → 检索知识条目及其 assumptions
  → 分解为原子子目标
  → 映射到 mathlib 定理
  → 生成 Lean theorem
  → lake build（内核检查）
  → 中文解释与形式化证明对齐
```

## 验证强度

| 方法 | 能排除什么 | 不能保证什么 |
|---|---|---|
| 数值抽检 | 大量明显错误 | 一般命题成立 |
| SymPy | 符号计算错误 | 完整逻辑、建模正确 |
| 人工审查 | 语义和策略问题 | 无疏漏 |
| Lean | 声明系统内的逻辑推导错误 | 形式化陈述符合原题本意 |

因此采用“双重可信边界”：

- **陈述审查**：人负责确认 Lean 命题忠实表达原题。
- **证明审查**：Lean kernel 负责确认结论由前提严格推出。
