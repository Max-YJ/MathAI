## 1. 背景解析

### 1.1 问题是什么？

大模型解数学题时，**只看最终答案对不对**（结果监督）来训练奖励模型，无法告诉模型 **哪一步推理错了**。论文研究：是否应对 **每一步推理** 给予监督信号？

### 1.2 为什么重要？

- **学术意义**：揭示数学推理能力的瓶颈可能在「过程」而非「结果」
- **应用价值**：过程监督模型 MATH 测试集上从 25.2% 提升到 58.0%
- **与 MathAI 的关系**：直接支撑 `calculus-solver` 等 Skill 的 **逐步校验铁律** — 无步骤验证不算解完

### 1.3 历史脉络

- 传统：RLHF 用 outcome reward（答案对错）
- 问题：错误推理可能碰巧得到正确答案（**虚假正例**）
- 本文：用人类标注的 **逐步正确性** 训练 process reward model (PRM)

## 3. 核心概念

### 概念 A：结果监督 (Outcome Supervision, ORM)

**内涵**：奖励模型仅根据 **最终答案是否正确** 给分。

**外延**：
- 适用于：答案空间小、中间步骤难以标注的任务
- 不适用于：需要可靠推理链的场景（长链数学推理）
- 与过程监督区别：ORM 无法惩罚「错过程对答案」

**在本文中的角色**：对照组 baseline。

### 概念 B：过程监督 (Process Supervision, PRM)

**内涵**：对人类标注的 **每一步推理** 判断正确/错误/中性，训练逐步奖励模型。

**外延**：
- 适用于：可分解为清晰步骤的任务（数学、代码、逻辑）
- 不适用于：步骤边界模糊、创意性任务
- 标注成本高，但推理时可用 PRM 做 **best-of-N 搜索**

**在本文中的角色**：核心方法。

### 概念 C：Best-of-N 搜索

**内涵**：生成 N 个完整解答，用 PRM 对 **每一步** 打分，选总分最高的。

**外延**：推理时策略，可与不同训练方法组合。

## 4. 论文核心分析思路

### 4.1 方法总览

```
数学题 → 模型生成逐步解答 → 人类标注每步正误
       → 训练 PRM（逐步分类器）
       → 推理时 best-of-N：生成 N 条链 → PRM 逐步打分 → 选最优
```

### 4.2 关键洞察

1. **虚假正例问题**：ORM 会奖励错误推理，PRM 可识别中间错误
2. **步骤级信号更密集**：每个样本提供多个训练标签（每步一个）
3. **推理时可搜索**：PRM 不仅用于训练，还可指导 test-time search

### 4.3 技术要点

| 模块 | 做法 | 设计理由 |
|------|------|----------|
| 数据 | MATH 数据集逐步人工标注 | 高质量过程标签 |
| PRM | 每步三分类：正/负/中性 | 细化监督粒度 |
| 评估 | Best-of-1860 on MATH | 充分展示 PRM 搜索能力 |

### 4.4 实验结论

- PRM 大幅优于 ORM（58.0% vs 25.2% on MATH test）
- 过程监督在 **泛化** 上也更好
- 局限：依赖昂贵人工逐步标注；步骤划分标准影响效果

## 5. 知识沉淀

### 5.1 可迁移的思想

| 思想 | 说明 | 在本仓库的应用 |
|------|------|----------------|
| **过程 > 结果** | 可靠推理需要逐步验证 | `calculus-solver` 每步 `calculus_verify` |
| **虚假正例警惕** | 答案对不代表过程对 | 终检 + 数值抽检 |
| **Test-time search** | 生成多条链再选优 | 可扩展：多路径解题后选校验全 PASS 的 |

### 5.2 可迁移的方法论

**过程验证清单**（适用于 AI 解题）：

1. 将解答拆为独立步骤，每步有明确「依据」
2. 对每步运行可自动化检查（SymPy / 单元测试）
3. 任一步 FAIL 则整条链不可用
4. 最终答案需与过程一致（回代验证）

### 5.3 关键算法（Best-of-N + PRM）

```
for i in 1..N:
    chain_i = LLM.solve(problem)
scores_i = sum(PRM(step) for step in chain_i)
return chain_argmax(scores)
```
